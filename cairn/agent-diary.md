# agent-diary

## 当前结论

技能从 `dev-diary` 的单日日报抽出工作记录，版式固定为时间段、事项、投入、完成项、未完成项。公司工作与个人工作分开写。

## 决策记录

1. 配置只放日记目录、时区和公司项目名单（`name` + `aliases`）。命中项目只表示这条落在该项目下。
2. 落在公司项目下的内容，仍由技能判断是不是公司工作。编写技能、Project Cairn、知识库脚手架、日记规范、面试、课程，以及不服务交付的效率探索，归个人，并写一句归类理由。
3. 日记原文已标 `非项目工作`、`非项目开发`、`不进周报` 的，直接归个人。
4. 周报、OKR、公司例会上自己的同步，不挂具体项目，归入公司工作下的「公司事务」。
5. 投入时间只采用原文写出的时长。没有就写「未记录」，不估算，也不把一天凑成 8 小时。
6. 默认只在对话里输出。用户要求写回时，只替换日报的 `# 3 工作记录`，流水和总结保持原样。
7. 技能设置 `disable-model-invocation: true`，只在用户点名或明确要求整理日记时运行。（该条已作废，见下方 2026-10-10 同日更正。）

## 更正（2026-10-10）

技能名由 `obsidian-diary` 改为 `agent-diary`。`agent` 指 Cursor、Claude Code 这类 AI 编程代理：技能由它们主动调用，目录名也不再绑定日记所在的笔记软件。日记路径仍在配置的 `diary_dir`。

同日再改配置加载：用户级默认放在当前编程工具的用户目录（Cursor 为 `~/.cursor/.agentdiary/config.yaml`，Claude Code 为 `~/.claude/.agentdiary/config.yaml`）。项目要改的字段写在项目根 `.agentdiary/config.yaml`。技能包内不再放运行时 `config.yaml`。

同日再改字段：用户级只保留 `diary_dir`、`timezone`、`daily_name`。首次缺少用户级文件时先询问再写入。每个项目必填 `type`（`company` / `personal` / `other`）、`name`、`department`，只写在项目级。`type` 决定公司日志、个人日志或其它；名称和部门写进该栏目。原先放在用户级的 `work_projects` 名单作废。

同日补上缺日报与写回：`ask_create_diary` 默认 `true`，缺文件必须问是否新建，选项里可以改成以后不再问。该键用户级、项目级都可写，项目级优先。`false` 时改看 `create_if_missing`。写回是把总结合并追加进 `# 3 工作记录`，不整节替换，也不改流水和总结。

同日增加跨项目统一工作日志：一次运行只使用当前编程工具的用户级配置。`project_dirs` 列出仓库根目录，各项目的类型、名称、部门仍只读该仓库的 `.agentdiary/config.yaml`。时间段内的日报合成一份日志；写回再按日期拆回各天。

同日收窄范围：本技能只整理日报。按周汇总不在本技能内，相关描述已从 `skills/agent-diary/SKILL.md` 移除。

同日改默认范围：未明确限制时，按跨项目、跨会话整理。流水与已有工作记录都参与去重；时间、投入或完成状态冲突时先问用户，不自行取舍。

同日改首次询问：用户级文件已在时，不再询问 `project_dirs` 或仓库根目录。当前工作区缺 `type`、`name`、`department` 时，只问这三项并写入该项目的 `.agentdiary/config.yaml`，问完之前不整理。其它项目不询问。`project_dirs` 里已有配置且名称对得上就用配置；对不上的按日记自己判断栏目，部门写「未记录」，并写归类理由。用户把范围限制为当前项目时，对不上的仍进待确认。

同日取消项目级配置：不再使用项目根 `.agentdiary/config.yaml` 与 `project_dirs`。类型、名称、部门改记在当前工具用户级的 `projects`，以仓库绝对路径为键。当前路径没有记录时，技能推测三项并追加，然后继续整理，不询问。已有记录则沿用类型和部门；名称可按日记标题改写。不知道路径的项目只在当次结果里判断，不写入名单。

同日去掉 `disable-model-invocation: true`：该字段在 Claude Code 下让模型不能自行调用本技能，且技能 description 不进上下文；Cursor 认同一字段，效果等同只认 `/agent-diary`。这与「用户点名 agent-diary，或明确要求整理开发日记」的触发口径冲突——按字段的语义，自然语言点名不会触发它。改由 description 里那句约束承担触发范围（用户没提就不读日记、不写文件）；用户仍可直接敲 `/agent-diary`。副作用是 frontmatter 只剩 `name` 与 `description`，落回通用 Agent Skills 规范的 6 个允许字段内，以后上传 claude.ai / Skills API 或走 `package_skill` 不会再因规范外字段硬报错。

同日补归类的两种日记写法：原规则只认「标题含项目名，其下内容归该项目」，而 dev-diary 近 5 天里有 4 天没有 `## 1.x 项目名` 分节，项目名写在条目里。现补扁平写法（按事项自身一级条目的标题，含加粗部分，匹配 `name` 或 `aliases`）、容器条目（文字只有项目名或项目名加时间的条目当分节用，不单独成事项，其时间给没有自己时间的下级条目），并给 `projects` 增加可选 `aliases`，用于「袜业库」这类简称。同批补时间写法归一化（全角冒号、单数字小时、`（09：00～）` 开区间）、条目正文里顺带提到的钟点不拆事项、`<!-- … -->` 注释块按正文读取；去重把已有的 `# 3 工作记录` 一起算，同一件事一次写成流水句、一次写成完成项视为同一条。

同日遗留（尚未改）：宿主判定仍无依据（Claude Code 侧有 `CLAUDECODE`，Cursor 侧 Anthropic 未定义，跨宿主的 `.agents/skills/` 更判不出来）；`diary_dir/template/日记-天.md` 仍是硬编码约定；模板把 `归类理由` 放在 `#### 事项` 下，而理由其实是项目级的；`projects` 的 `path` 必填，导致「展厅商机」这类不知道仓库路径的项目每次重新猜栏目；单日标题写 `# YYMMDD 工作记录`、多日写 `# YYYY-MM-DD～… 工作日志`，口径不一；技能会静默把推测出的项目写进用户级配置，输出里没有回显。

同日改掉上面遗留里的三条：① 当前工作区不在 `projects` 里时不再静默追加，改为先推测 `type`、`name`、`department` 并把路径与三项一起问用户确认，本轮不整理，确认后才写入；用户说不用记时只在本次用推测值。② `归类理由` 由 `#### 事项` 下移到 `### 项目名称` 下，理由描述的是项目为何落在该栏目，原先会按事项重复同一句。③ `path` 改为可选，不知道仓库路径的项目可按 `name`（配 `aliases`）只记一条，归类时照样对上，用于「展厅商机发现」这类反复出现但找不到仓库的项目。剩下的遗留是宿主判定、模板路径硬编码、单日与多日标题口径。

同日去宿主化并改新建来源：① 用户级配置不再按宿主分文件，统一到 `~/.agentdiary/config.yaml`。原设计要技能判断「当前宿主」，而 Claude Code 侧只有 `CLAUDECODE`、Cursor 侧 Anthropic 未定义，装在多宿主共用的 `.agents/skills/` 时更判不出来；失败模式是在一个工具里把项目静默写进另一个工具的配置，比报错更难发现。随之去掉「一次只覆盖当前这个编程工具」的范围限制与输出里的工具名行（工具只能靠猜）。旧的两份宿主机配置留一次性迁移规则，读旧的迁到新路径。② 新建日报不再读硬编码的 `diary_dir/template/日记-天.md`，改为照最近一篇已有日报的骨架写（前行言、两个标题、`# 2 总结` 的小节标题，清掉流水与勾选）；往前找不到才退回「一节流水 + 一节总结」。遗留项里的宿主判定与模板路径两条随之关闭，只剩单日与多日标题口径一条。

同日把项目名单搬进日记目录：由用户级 `~/.agentdiary/config.yaml` 的 `projects` 改为 `<diary_dir>/agentdiary.md`，一节一个项目（`## 名称` 加 `- 类型：`、`- 部门：`，`- 路径：`、`- 别名：` 可选）。理由是名单属于日记内容而非机器配置，放进 vault 可在 Obsidian 里直接改，用户级配置只留日记目录、时区、文件名和缺日报的两个开关。写法取小节列表而非表格或内嵌 YAML——与日记输出里 `- 部门：` 那套写法一致，长路径也不挤版；用户对比后选定这一种。文件不存在或没有项目小节都不算错，不预先建空壳；新增项目仍先问用户再追加。本机已建 `dev-diary/diary/agentdiary.md` 并从用户级配置去掉 `projects`。
