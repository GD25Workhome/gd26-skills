## 进入项目后的阅读顺序

1. 先读本文件（`AGENTS.md`）。
2. 若 `cairn/ROADMAP.md` 存在，则阅读它以了解路线图、当前焦点和开放问题（ROADMAP 是可选的；最小化初始化的项目可能还没有它）。
3. 阅读 `cairn/LOG.md` 中最新的若干条记录（最新的在最上面），了解近期进展和关键决策。
4. 根据手头任务的需要，阅读相关的 `cairn/` 知识专题文档。

## 文档职责

| 文件 | 作用 | 维护方式 |
|---|---|---|
| 根目录 `AGENTS.md` | 规则与导航 | 极少变更，≤ 60 行 |
| 根目录 `CLAUDE.md` | 一行 `@AGENTS.md` 的占位 | 一次性写入，之后不再触碰 |
| `cairn/ROADMAP.md` | 路线图与进度 | 原地更新，保持精简 |
| `cairn/LOG.md` | 时间线日志 | 新条目加在最上方（最新在前），每条 ≤ 20 行，只写摘要 + 指针 |
| `cairn/<topic>.md` | 知识专题文档（当前真相） | 原地更新；踩坑写在正文小节，用 `contains` 标注；修订在 LOG 留指针 |
| `cairn/Reference/` | 外部原始输入 | 按需创建；只追加不改写 |
| `cairn/Cited.md` | 知识库引用清单 | 只写指针，从不复制原文 |

> 其余文档只在出现具体信号时才创建（需要记录一项决策、解决了一个踩坑、目标跨过单次会话）——不预先搭空壳。工程资产（被代码或流程直接消费的契约 / 配置 / 规格）不由本系统管理；它们留在代码树中，不进 `cairn/`。

## 工作笔记命名规则

非骨架工作笔记（`cairn/` 之外、也不在上述固定名清单中的任何文件）必须遵循 `.cairn/config.yaml` 中的 `cairn.language`：

- `language: zh` → slug 使用中文（例如 `修复-登录bug`、`需求评审-会议纪要`）。
- `language: en` → slug 使用英文（例如 `fix-login-bug`、`requirements-review`）。

文件名一律经 `save-md-artifact` 生成（输出形如 `YYMMDD-NN-<slug>.md`）；不要手动加 `0-` / `1-` 前缀、用裸 `note.md`，或只用阶段编号作为文件名。阶段 / 阶段编号写在 frontmatter 的 `stage` 字段里，不进文件名。审计会标记任何绕过本规则的工作笔记。

## 冲突仲裁规则

- 优先级：**知识专题文档 > LOG 历史**；规则级冲突由本文件裁决。
- 业务 / 设计结论以 `cairn/` 知识专题文档中的最新记录为准，不以更早的 LOG 条目为准。

## 知识库消费反射

- 在开始一项工作之前——若其可复用内核（它将产出或依赖的任何结论）具备毕业价值——先查 {{KNOWLEDGE_INDEX}}；只对真正影响了产出的笔记往 `cairn/Cited.md` 追加一条（只写指针，从不复制正文）。

## 文档协作规则

- 动手改之前，先判断用户要的是「讨论 / 建议」还是「直接改文档」；当用户说「先看看 / 先评估」时，先给分析——不要直接改写正式文档。
- 纠正过往判断时，追加更正说明；不要静默覆盖。
- 不要把未经确认的判断写成既定事实。

## 知识沉淀规则

- 每完成一个有实质进展的步骤，就在 `cairn/LOG.md` 顶部追加一条（摘要 + 指针）；让结论沉淀进 `cairn/` 知识专题文档。
- **完工回复闸门：**在做出任何「完工」类声称之前——包括但不限于：工作已完成或已实现、已定稿、已更新、已同步、已验证或测试通过；问题已修复或已解决；交付物已可使用；工作已结束；以及语义等价的措辞——先执行 `references/maintenance.md` 中的 Cairn 检查点；只更新其触发矩阵要求的记录，核验后再回复。若用户明确要求只读 / 禁止编辑，则禁止写入 Cairn。
- 跨项目可复用的经验，通过毕业机制沉淀到 {{GRADUATION_TARGET}}。
