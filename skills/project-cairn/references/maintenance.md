# maintenance

有实质进展后的持续行为。以阅读项目 `AGENTS.md` 为规则驱动——没有自动的对话结束钩子。

## 完成回复门禁

在任何完成性声明之前运行此检查点，包括但不限于：工作已完成或已实现、已定稿、已更新、已同步、已验证或测试通过；问题已修复或已解决；交付物已可用；声明工作已结束；以及语义等价的措辞。不因解释、只读评估、等待确认、工作受阻，或无实质进展的工作而触发。

1. 判断本次工作改变或得出了什么。
2. 仅维护矩阵条件已满足的那些记录。
3. 校验已变更的记录。
4. 然后发送完成回复。

| 记录 | 何时维护 | 全局约束 |
|---|---|---|
| `cairn/LOG.md` | 有实质进展。 | 追加简短的最新优先摘要与指针；不要把长结论放进 LOG。 |
| `cairn/<topic>.md` | 出现稳定结论、决策、教训或可复用模式。 | 把当前真相放在聚焦的知识专题文档中。 |
| `cairn/ROADMAP.md` | 项目状态已变。 | 仅在焦点、里程碑或开放问题变化时就地更新。 |
| `cairn/Cited.md` | 来自已配置外部知识库的知识确实塑造了输出。 | 只存指针；不要机械创建或更新。 |

显式的只读或禁止编辑请求优先：不要写入 Cairn 文件，并说明哪些候选记录被推迟。

完成回复仅在此检查点对所变更记录的自检通过后才能继续：

- 本检查点新增或修改的每条 `cairn/LOG.md` 条目处于正确的最新优先位置，且 ≤20 行；每条此类条目中的本地 Markdown 细节指针都能解析到已存在的目标。此处不要扫描或因无关历史条目而阻塞；更广的历史检查属于 `cairn audit`。
- 每篇新的 AI 生成专题具有合法 YAML frontmatter，含 `type: project_topic`、`authoring_mode: ai_generated`，以及内联 `contains` 列表，其值与实际内容匹配（例如决策用 `decision`，已解决的坑用 `lesson`）。不要发明另一套 schema。
- 仅当项目状态变化时才改 ROADMAP。

任一检查失败，先修好记录再回复。

## 规则

- 有实质进展后，在 `cairn/LOG.md` 顶部新增一条（逆时序，最新在前）：发生了什么、决定了什么、指向细节。每条保持简短（≤ ~20 行）。
- 出现稳定结论、决策、教训或可复用模式时，更新或创建 `cairn/<topic>.md`。从 `assets/templates/topic.md` 创建专题；只保留有内容的正文节。
- 当可识别的人类实质形成了某专题的知识时，将其加入专题 frontmatter 的 `contributors` 列表；无法安全解析身份时先询问，勿发明身份。
- 专题可在其形成/背景节内包含 `### Origin quote`（按 `zh-glossary.md` 翻译），仅当简短直接摘录能实质还原现场且可安全保留时。包含发言人/核定角色、日期与语境；无合适引述时整节省略。
- 保留原文措辞。有限脱敏须显式标注（`[redacted]` / `[已脱敏]`）；若安全使用需要大幅改写，写场景摘要，勿标成引述。
- 已解决的坑写入相关专题的教训区，并在 `contains` 中加入 `lesson`。若尚无专题，该坑触发创建专题——不要另起统揽式 `PITFALLS.md`。
- 使用了已配置外部知识库中的知识时，更新 `cairn/Cited.md`（见 `consume.md`）。
- 不要把长结论放进 LOG——LOG 存摘要与指针；结论住在知识专题文档中。
- 在专题中就地更正旧结论，并在 LOG 中加指向该修订的指针。不要静默覆盖。
- 工程资产留在 `cairn/` 之外。只有*关于*资产的知识（如何构建、坑、设计理由）可进入 `cairn/`。
- 当探索分支被合并、放弃或回滚时，做分支关闭复盘（见 `branch-closure.md`）：将其 `cairn/` 变更分类为 discard / merge-to-project / graduate / archive-reference，以免有价值知识随分支丢失。
- 撰写 `cairn/LOG.md` 与专题正文时，一律遵循项目 `.cairn/config.yaml` 中的 `language`，并按 `references/init.md` → 文档语言：中文直接用中文模板口径；非中文则从中文模板翻译后再写入。
- 创建非骨架 md（`cairn/` 固定名之外的任何文件）时，经 `save-md-artifact` 路由，并按 `.cairn/config.yaml` 中 `cairn.language` 设定的语言写 slug（`zh` → 中文 slug，`en` → 英文 slug；见 `AGENTS.md` → 工作笔记命名规则）。阶段/期次编号写在 frontmatter `stage`，永不进文件名。绕过此规则的工作笔记由 audit 标出。
