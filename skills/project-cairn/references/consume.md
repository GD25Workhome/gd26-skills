# consume

从已配置的外部知识库拉取并引用知识到当前项目。

## 何时

在开始一项工作（写代码、做技术决策、排查错误）之前，先做 **毕业对称测试**：这项工作将产出——**或依赖**——的任何结论，是否够格成为毕业候选（见 `graduation.md` → Candidate criteria——对尚未完成的工作，按可复用性与抽象标准判断；验证与可追溯性只能随工作本身而来）？若是，先查 INDEX——别人可能已经毕业过同类结论。

「产出或依赖」很重要：工作的交付物本身可能纯属项目本地（本仓库的 CI 配置文件），而其内的可复用内核（如何组织 CI caching、要避开哪些坑）正是另一项目可能已经毕业的内容。测试的是工作的可复用内核，不是交付物。

项目自身的 `cairn/` 知识专题文档优先：先查阅它们，仅对项目自身尚无记录结论的部分再触发 INDEX 检查。

在暂缓对接 provider（`.cairn/config.yaml` 中 `graduation.provider: none`）时，尚无外部 INDEX 可查：该反射退化为仅查项目自身的 `cairn/` 知识专题文档，直到首次毕业时连接知识库（`graduation.md` → Deferred provider）。

应用该测试的示例（非穷尽列表）：

- 集成本项目尚未用过的外部 API/SDK，且此类集成经验通常可复用 → 查。
- 某错误的*解法形态*可复用，且本项目自身笔记无相关内容 → 查。
- 技术/架构选型决策，本项目尚无记录结论 → 查。
- 用户直接问「X 该怎么做」，而本项目对该领域尚无定论 → 查。
- 配置本仓库 CI caching——交付物（项目本地配置文件）不可复用，但工作依赖另一项目可能已毕业的可复用知识 → 查。
- 纯项目内部细节判断（给变量命名）——工作中任何地方都无可复用内核 → 不查。

检查成本很低（任意规模下，首次阅读都是标题 + 摘要，而非笔记正文——见 Retrieval）；测试说 yes 时，偏向去查。精度落在下方的引用步骤，不在此处。

## 检索

如何*找到*候选笔记，随知识库规模放大。入口是 `.cairn/config.yaml` 中的 `graduation.index`。

- **数十篇笔记（扁平 INDEX）** — 自上而下通读 INDEX；一行一篇的全量扫描仍是最便宜可靠的选项。
- **数百篇（分层 INDEX）** — 先读顶层领域索引，下钻到相关领域子索引，再扫描。
- **再往上（查询优先）** — 不要扫描；先查询。运行下方漏斗，INDEX 保留为召回安全网。

查询漏斗——使用 provider 原生查询接口（`provider-interface.md` → Read side；优先于原始 grep，不可用时显式回退）：

1. 按任务领域词做 **结构化/标签查询**（frontmatter 属性、标签）。
2. 结构化/标签未命中时，在知识库容器范围内做 **全文搜索**。
3. 从任意命中做 **图谱扩展**——在下结论前沿链接/反向链接看相邻笔记。
4. **回退扫描** — 查询未命中不等于证明不存在；最后用扁平方式扫描相关（子）INDEX。

每一层的阅读单位相同：索引行或查询结果给出标题 + 摘要；仅打开看起来相关的笔记正文。

## 如何做

1. 按上方 **Retrieval** 定位候选笔记。
2. 只读相关的外部笔记。
3. 在写入任何 `cairn/Cited.md` 条目之前，应用 **采用门槛**：只有当其结论被采纳或改编进当前工作的具体产出——做出了决策、采用了代码路径、应用了修复——时，笔记才配得上一条条目。查了 INDEX、打开了笔记、发现不适用或仅松散相关 → 不记条目；无痕跳过。检查不等于承诺引用。
   - 采用包括 **排除法式采用**：一篇笔记通过排除某条路径而塑造了判断（「因为这篇笔记我们没走 Y 路」）已影响具体产出，也配得上一条条目。门槛是「影响了具体产出」，不是「逐字照抄」。
4. 对每篇过线的笔记，向 `cairn/Cited.md` 追加一行指针：拉取了什么、为何、适用于何处，以及回指源笔记的链接。首次使用时从模板创建 `cairn/Cited.md`。
5. 永远不要把外部知识笔记全文复制进项目——复制从做成那天起就开始腐烂。回链并在需要时重读最新版本。
6. 仅用项目特定结论或改编更新项目知识专题文档，不要整段复制知识库正文。

`Cited.md` 是指针列表（知识正文住在知识库）。`cairn/Reference/` 不同：它存放项目完全拥有的原始外部输入。两者保持分离。
