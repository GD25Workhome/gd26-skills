# agent-diary

把开发日记整理成工作记录：时间段、事项、投入时间、完成项与未完成项。栏目由项目类型决定：公司、个人或其它。

先在对话里给出结果。用户明确要求写回日记时，才改日报。当前工作区的项目记录可以在确认后写入用户级配置（见「步骤」），这不算写回日记。

## 何时运行

用户点名 `agent-diary`（用户直接敲 `/agent-diary` 也算点名），或明确要求总结 / 整理开发日记、工作日志。没有这句要求，就不读日记、不写文件。

默认范围是跨项目、跨会话，一次给出一份统一工作日志。日记正文里没写工具时，不猜测某条是哪个工具写的。

会话指各次记日记和整理留下的内容：时间段内日报的流水，以及已有的 `# 3 工作记录`。不因当前仓库或这次对话只谈到其中一部分，就丢掉其余项目、其余会话的记录。

只有用户明确限制时才收窄，例如「只要当前项目」「只要这个会话」「只看某一个项目名」。没说限制，就用默认范围。

只整理日报。用户要按周汇总时，停止并说明本技能只处理日报。

## 配置

两层，路径都与宿主无关：

- **用户级**：`~/.agentdiary/config.yaml`，放 `diary_dir`、`timezone`、`daily_name` 三个必填项，以及 `ask_create_diary`、`create_if_missing`。形态见 [config.example.yaml](config.example.yaml)，它只是示例，不参与运行。
- **项目名单**：`<diary_dir>/agentdiary.md`，跟着日记走。形态见 [agentdiary.example.md](agentdiary.example.md)。

用户级配置里不放项目名单；也不读、不写项目根的 `.agentdiary/config.yaml`。

`~/.agentdiary/config.yaml` 不存在，而 `~/.claude/.agentdiary/config.yaml` 或 `~/.cursor/.agentdiary/config.yaml` 存在时（旧版按宿主分开写的那两份），读旧文件、原样迁到新路径，说明已迁移，再继续；旧文件里若有项目名单（`projects` 键），一并迁进 `<diary_dir>/agentdiary.md`。迁移只做一次。

当天日报还不存在时，用用户级的 `ask_create_diary`。没写则视为 `true`。

| 值 | 行为 |
| --- | --- |
| `true` | 必须询问是否新建 |
| `false` | 不再询问，改看 `create_if_missing` |

`create_if_missing` 没写则视为 `false`。只在 `ask_create_diary` 为 `false` 时使用：`true` 直接新建，`false` 不新建并停下来说明。

### agentdiary.md

一节一个项目，`## ` 后面写名称，下面用 `- 字段：值` 写这三行，另两行可选：

| 字段 | 作用 |
| --- | --- |
| 类型 | `company` 进公司日志，`personal` 进个人日志，`other` 进其它 |
| 部门 | 写在同一栏目下的部门。看不出来就写「未记录」 |
| 路径 | 可选。仓库根目录的绝对路径，用来认出当前工作区。没写路径的项目，只在归类时按名称、别名对上 |
| 别名 | 可选。日记里对该项目的其它叫法（如「袜业库」之于「大唐袜业」），归类时与名称一同比对 |

同一名称只保留一节。文件不存在、或里面没有项目小节，都不算错，不为此询问。要新增项目时按「步骤」第 3 条问完用户再写。

### 第一次使用

用户级文件不存在时，先初始化，本轮不整理日记：

1. 询问 `diary_dir`。用户没给出可用目录就停，不要沿用模板里的示例路径。
2. 请用户确认 `timezone: Asia/Shanghai` 与 `daily_name: "{yy}{mm}{dd}.md"`。同意就用这两项，用户给了别的值就用用户的值。
3. 写入 `~/.agentdiary/config.yaml`：上面三项，加上 `ask_create_diary: true`。不要在这时写入 `create_if_missing`，也不要建 `agentdiary.md`。

## 步骤

1. 读配置。默认按跨项目、跨会话收集；用户明确限制了范围时，只收集该范围。
2. 确定时间段。用户没指定时，用配置里的 `timezone` 取今天。单日接受「今天 / 昨天 / 前天」、`YYYY-MM-DD`、`YYMMDD`、「M月D日」（年份用该时区的当年）。一段时间接受「从 A 到 B」、`A～B`、「最近 N 天」（含今天）。不包含今天之后的日期。用 `daily_name` 得到每一天的文件名。
3. 先认当前工作区。读 `<diary_dir>/agentdiary.md`，用仓库根目录的绝对路径对照各项目的「路径」。
   - 已有这一节：沿用它的类型和部门。日记里该仓库的项目标题与小节名称不一致时，把小节名称改成日记标题；部门仍是「未记录」且日记写明了部门时，补上部门。不要因为再次推测而改写已有的类型。
   - 没有这一节：根据仓库内容和日记推测类型、名称、部门，把路径和这三项一起问用户确认，本轮不整理。用户确认或改正后，按用户给的值往 `<diary_dir>/agentdiary.md` 追加一小节（文件不存在就连 `# agentdiary` 标题一起建），再继续整理。用户说不用记时，只在本次用推测值，不写文件。类型只写 `company`、`personal`、`other`；部门看不出来就写「未记录」。
   - 用户限制为当前项目时，只用这一节。
   - 日记里出现、但不知道仓库路径的项目，不为此询问，也不自动写进 `agentdiary.md`。
4. 读时间段内的日报。某一天不存在时按「缺日报」处理，不要自己新建。一段时间里缺多篇时，把缺的日期列在同一次询问里。选「不新建」就跳过这些日期，用已有日报继续；时间段里一篇都没有就停。
5. 流水和已有的 `# 3 工作记录` 都作为输入，以便跨会话去重。`# 2 总结` 里的感想不另开事项。`<!-- … -->` 注释块按正文读，里面的 `非项目工作`、`非项目开发` 这类标记照常生效。用户限制为「这个会话」时，只用本次对话里明确说过的工作，不把整份日报都算进来。
6. 按下一节归类，并按「去重与冲突」处理。先在对话里给出一份统一工作日志。有冲突时先问，该条不写回。
7. 用户要求写回时，按「写回」一节把本次总结合并进已有工作记录。跨越多天时按日期拆开，分别合并进对应那天的日报。

### 缺日报

按 `ask_create_diary` 处理，并写出期望路径。

`true` 时先问，本轮不整理。选项：

1. 新建这一篇，下次仍问。
2. 不新建，下次仍问。
3. 以后缺日报都新建，不再问。
4. 以后缺日报都不新建，不再问。

选 1 就新建这一天。新建时照**最近一篇已有日报**的骨架写，不去读任何固定模板文件。

- 从这一天往前按 `daily_name` 逐个日期找，取日期最近、能读到的那一篇（不必回溯太远，30 天内没有就按下面兜底）。
- 照抄它的骨架：`# 1 流水日记` 之前的前言行（如待办链接）、`# 1 流水日记` 与 `# 2 总结` 两个标题、`# 2 总结` 下的小节标题（如 `+ 核心（今天在想什么）`、`+ 好的地方`、`+ 不好的地方`）。
- 不带内容：流水条目、勾选状态、`# 3 工作记录` 都清掉。`# 1 流水日记` 下留一行空的 `- `，`# 2 总结` 的各小节留空。
- 往前找不到任何一篇时，才写一节 `# 1 流水日记` 和一节 `# 2 总结`，并说明没有可参照的日报。

建好后若流水是空的，说明文件已建、还没有可总结的流水，然后停。选 2 就停。

选 3 或 4 时只改 `~/.agentdiary/config.yaml`。选 3 写 `ask_create_diary: false` 与 `create_if_missing: true`，然后按上面的方式新建。选 4 写 `ask_create_diary: false` 与 `create_if_missing: false`，然后停。

`false` 时不再提问：`create_if_missing` 为 `true` 就新建，为 `false` 就停并说明当前配置不再新建。

## 归类

对照 `<diary_dir>/agentdiary.md` 里每一节的名称和它的别名；多个都能对上时，用最长的那个。用户限制为当前项目时，只对照当前路径那一节。

日记有两种写法，都要认：

- **分节写法**（如 `## 1.1 大唐袜业`）：分节标题含某个名称，其下内容都归这个项目，直到下一个同级或更高级标题。
- **扁平写法**（如 `- （09:00～09:56）切个人分支，准备读问数`）：没有分节标题，就看**事项自己的一级条目**——条目的标题（含加粗部分）里出现某个名称或别名，这条就归这个项目，它的下级条目跟着走。
- 一级条目的文字只有项目名（或项目名加时间，如 `- （09：00～）大唐袜业`）时，它只是分组容器，当作分节用，不单独成事项；它的下级条目才是事项。容器上的时间不单独成事项，但下级条目没有自己时间时，时间段沿用容器的这个值。

一级条目在分节里时，优先进所在分节，不再看它自己的文字。周会里其他人的发言不计入。

名单里对上的项目，栏目由类型决定，标题用小节名称，其下写部门；有归类理由时，也写在项目标题下这一层：

- `company` → 公司日志
- `personal` → 个人日志
- `other` → 其它

对不上任何一个已记录项目时，不要问。

- 用户把范围限制为当前项目：放进「待确认」，原因写「对不上当前项目名称」。
- 没有这层限制：标题用日记里的项目标题，部门写「未记录」，栏目自己判断，并在该项目下写归类理由。不把这些项目写进 `agentdiary.md`。原文已标 `非项目工作`、`非项目开发`，或主体是技能、知识库脚手架、日记规范、面试而不是项目交付的，归个人日志。能看出是公司交付的归公司日志，是个人事务的归个人日志，两者都不是的归其它。仍判断不了栏目的放进「待确认」，原因写「栏目判断不了」，不要为此停下来问。

已经归进名单中某个项目的条目，若原文已标 `非项目工作`、`非项目开发`，或主体是技能、知识库脚手架、日记规范、面试而不是该项目交付，改归个人日志，并在该项目下写一句归类理由。拿不准的放进「待确认」，保留原句。

### 时间与完成状态

写法先归一化，再判别：

- 全角 `：` 与半角 `:` 等价；单数字小时补零（`9:00` → `09:00`）；`（09：00～）` 只有开始时间时，时间段写 `09:00～`。
- 条目正文里顺带提到的钟点（如 `～12:00，数据库迁移完成`）不是这条的独立时间段，也不因此拆事项。
- `（11:30～13:45）` 配有 `1.5H`：时间段与投入都照录。
- 只有钟点，如 `（8:40）`：时间段写该钟点，投入写「未记录」。
- 没写时间：时间段和投入都写「未记录」。
- 不估算，不把一天凑成 8 小时。时段重叠就各自保留，并在该事项下加一行「时段重叠」。
- `[x]` 或带完成标记的子项归「完成」；`[ ]` 归「未完成」。
- 没有复选框时：已经发生的结果归「完成」；「待定 / 还要 / 尚未」归「未完成」。仍无法判断就放进「待确认」。

一项事项对应一条带独立时间，或项目下的一条一级条目。它下面的勾选是这项的细节，不拆成新事项。子条目自己带了时间段时，单独成事项。

### 去重与冲突

同一项目、同一事项下，完成或未完成的句子意思相同，只留一条。时间段、投入彼此相同，或一边是「未记录」、另一边有具体值，视为同一条事项，并采用那个具体值。

比对时把已有的 `# 3 工作记录` 一起算进来：同一件事一次写成流水句、一次写成完成项，属同一条，不重复追加。

下面的情况是冲突，两条都列出来问用户，不自行取舍，问完之前不写回这条：

- 时间段对不上，且都不是「未记录」
- 投入对不上，且都不是「未记录」
- 同一件事一边在完成、一边在未完成
- 两条描述互相否定

用户选定或给出合并结果后，才采用那一版。

## 对话输出

```markdown
# YYMMDD 工作记录

## 公司日志

### 项目名称
- 部门：部门名称
- 归类理由：名单里没有这个项目、自己判断栏目时填写

#### 事项
- 时间段：
- 投入：
- 完成：
  - …
- 未完成：
  - （无）

## 个人日志

### 项目名称
- 部门：部门名称
- 归类理由：改归个人，或名单里没有这个项目、自己判断栏目时填写

#### 事项
- 时间段：
- 投入：
- 完成：
  - （无）
- 未完成：
  - …

## 其它

### 项目名称
- 部门：部门名称
- 归类理由：名单里没有这个项目、自己判断栏目时填写

#### 事项
- 时间段：
- 投入：
- 完成：
  - …
- 未完成：
  - （无）

## 待确认

- 原句：…
  - 原因：…
```

同一项目内按日期、再按时间段先后排；没有时间的放在该日末尾，保持原文顺序。跨项目时，已在 `agentdiary.md` 里的项目按文件里的顺序排；名单里没有的，按在日记中第一次出现的顺序排在后面。时间段多于一天时，每条事项加上 `- 日期：YYYY-MM-DD`。标题写成这段时间，例如 `# 2026-10-08～2026-10-10 工作日志`。某一栏目没有条目时仍保留标题，下面写「（无）」。末尾用一句话给出公司、个人、其它、待确认的事项数。

完整示例见 [examples.md](examples.md)。

## 写回

用户要求写入、写回、更新日记时才改日报。把本次总结合并进已有内容，不覆盖整篇，也不整节替换。

- `# 1 流水日记` 与 `# 2 总结` 保持原样。
- 还没有 `# 3 工作记录` 时，把它追加到文件末尾。
- 已有该节时：先按「去重与冲突」，把本次每条完成项、未完成项与已有事项里的句子逐条比对。意思相同的不重复追加，已有句子不改写。时间段或投入原来是「未记录」、本次有具体值时，只补上这个值。冲突项等用户回答后再写。
- 待确认只追加新的原句；意思相同的不重复。不删已有条目。
- 写完后读回核对：流水还在，`# 3 工作记录` 只有一节，原有事项还在。
- 跨越多天时，对话里仍是一份统一日志；写回按事项上的日期拆开，各自合并进那天的日报。某一天没有本次事项，就不改那个文件。

## 安装

把本目录原样复制到宿主的 skills 目录，目录名保持 `agent-diary`：

- Cursor：`~/.cursor/skills/agent-diary`（也可用仓库 `scripts/sync-skills-to-cursor.sh`）
- Claude Code：`~/.claude/skills/agent-diary`
- 认 `.agents/skills/` 约定的应用：`~/.agents/skills/agent-diary`
- 其它认 Agent Skills 的应用：该应用自己的 skills 目录

配置不随技能目录走：用户级固定在 `~/.agentdiary/config.yaml`，缺文件时按「第一次使用」询问后写入；项目名单写在 `<diary_dir>/agentdiary.md`，跟着日记走。不使用项目根配置文件。
